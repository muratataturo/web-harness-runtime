Astryxは部品と設計基盤であり、地図や人生の計画そのものを生成する機能ではない。このruntimeで相談内容と視覚成果物の型を対応付けた。図がなくてもよい単なる価格・在庫確認や宿の比較には、地図を強制しない。

## 「当たり前品質」の契約

`src/visual-artifact.ts`と`config/ux-quality.json`に定義した。

- 行程は`journey-map`。場所と実際の行動手順を結び付け、`primaryStepId`で主な活動の時刻を指定する。前後の移動手順と、到着後の主な活動を混同しない。
- 地点名は48文字以内で場所だけ。時刻や行動説明を入れない。表題は64文字以内、概要は180文字以内。詳細は選択した地点と元の手順で読む。
- ピンには引用中の名前付き緯度・経度を要求する。取れない場所は未配置の一覧へ残す。施設代表点を入口や休憩席の位置として扱わない。
- 地図の破線は配置できた地点の訪問順で、通行可能な道路や実測の徒歩経路ではない。地点選択は行程側と連動。任意の立寄りを省くと、紐づく費用も比較できる。時刻の再計算は行わないと明示する。
- 人生は`life-roadmap`。領域×期間に、具体行動・完了目安・前提・判断条件を置く。循環参照や不明な節目を拒否する。前提が終わるまで後続の完了操作を抑止し、前提を戻すと後続の完了も戻す。
- 将来の収入・採用・生活を予測として断定しない。提案と出典に基づく情報を分ける。進捗操作はこの画面内の仮操作で、実際の達成を自動認定・永続保存しない。
- 保存回答では10秒以内に視覚成果物を操作できること、最初の画面に図が始まること、4画面幅で横はみ出しがないことを自動検査する。人の理解・魅力の評価は別途10秒レビューで取得する。自動検査から人の評価点を作らない。

## 生成と自己改善

`finish_task.visualArtifact`を全エンジン共通の生成契約へ追加した。構造・引用・手順参照を検査し、不足には`accepted=false`を返す。視覚の修正は最大2回。その後は不足を残した部分回答とし、事実条件の成功には数えない。sandbox回収とservice評価でも同じデータを再検査する。

独立診断`diagnose`は`insufficient_visual_artifact`を改善計画に戻す。引用や既確認条件が悪化した候補は、図が追加されただけでは採用しない。Chatには「地図で行程を見る」「人生のロードマップを開く」を追加し、保存回答をHTMLとして配信する。

元の12件の調査引用を保持し、地図化の準備として座標に関する4件の引用を追加した。その保存スナップショットを入力に、事実を変えず視覚表現を改善する経路も追加した。

```sh
npm run build
node dist/cli.js improve <task-id> --offline-visual --mode auto --iterations 1 --timeout 180 --agent codex --model <利用可能なモデル>
node dist/cli.js export-html <採用されたtask-id> --out answer.html
```

`--offline-visual`はブラウザ・検索・shellをモデルへ公開せず、保存された本文・行動計画・引用から型付きデータを生成する。旅行では保存ページの写真候補を`inspect_photo`で実画像確認し、写真素材を取得・保存する。ホストは元の本文、候補判定、予算と根拠を保持し、共通改善ループで採用を判定する。現在はローカルのCodexに対応。モデル重みの学習ではない。地図の座標が保存されていなければ、先に許可された地理情報源を取得する必要がある。

地理検索には、許可URLへ`https://nominatim.openstreetmap.org/search`を明示して`locate_place`を使う。既存profileのドメイン範囲を暗黙に広げない。標準のお出かけ例ではこのURLを明示した。HTMLのJSON-LDにあるGeoCoordinatesも、実行せず、構造化メタデータと表示して取り込める。これらは施設の営業を裏付ける根拠にはしない。

## 検証と限界

[ブラウザ検証](evidence/visual-artifact-qa.json)は実モデルの最終HTMLを対象にする。PC/スマートフォン、地図タイルの実表示、選択連動、費用切替、Google Maps URL、ロードマップの依存関係、オフラインのピン操作、埋め込み文字列の安全性を検査した。

実表示の検証では、Astryxの論理画像サイズがLeafletタイルを幅0にする問題と、Reactの更新がLeaflet付与クラスを消す問題を発見して修正した。読み込み件数だけでなく、画像の表示寸法と地図枠内へのクリップを検査するようにした。

型・ビルド、全220テストと4画面幅のブラウザ検査を確認。この失敗から、修正依頼後にモデルが終了した場合も、引用検証済みの草案を部分回答として保持する処理と回帰検査を追加した。人間による新版の10秒理解・魅力度は未測定。背景地図はネットワークに依存する。自動ブラウザ検査は合成PNGで行い、公開タイルの走査はしない。実タイル確認は手動コマンドとして分離した。オフラインでは出典座標のピンと概略線、行程と費用の操作を残す。営業・料金・空席の再確認や、実際の道順の確定を、視覚改善の完了として置き換えない。

写真付き体験とGoogle Mapsプレビューの生成・検証手順は[旅行体験runtime](travel-experience-runtime.md)を参照。

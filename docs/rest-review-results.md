# 休憩場所の確認と修正観点の再利用

[実際に生成した浜松のHTML](hamamatsu-rest-confirmed.html#review-perspectives)。モデルの回答は人手で編集していない。以前の城周辺の休憩場所をそのまま確認済みに変更せず、取得した公式資料で場所と利用時間を確認できる休憩先へ差し替えた。

## 解消したこと

- 採用した休憩5手順は、場所を示すfactとopeningの検査が全て通過。未確認・失敗0件。
- 全21手順の検査はready、移動・滞在のstateもpassed。09:00出発〜20:00帰着を保持した。
- 館内の小型椅子と飲食店の客席を使用。具体的な利用位置、空席、継続着席、臨時変更は当日判断として残す。
- 展望回廊の「￥1,200」という公式表記を入館料の検出器が見逃していた不具合を修正。通常料金と団体料金の読み分けは引き続き必要。
- 公園の24時間開放を通常の時刻表記と分けて照合できるようにした。公園・天守閣・駐車場・受付の根拠を混同しない。

今回の行程は博物館とホテル周辺を中心にした案で、徒歩区間の推定約1.1km、徒歩本体32分、2人の掲載額による予算17,600円。距離は引用座標の直線距離×仮の迂回係数で、実道路距離ではない。以前の3.9kmの城周辺案と同じ訪問先ではなく、距離が短くなったことを品質向上の指標とはしない。

## 残る比較情報を分離

全体のライブ判定は**partial、strictLivePassed:false**を維持している。不採用にした浜松城公園の「無料条件」と「具体的なベンチの根拠」の2項目が未確認で、モデルがこれらを必須の比較条件へ含めたため。主案にはこの公園ベンチを使っていない。休憩の未確認が残っているという意味ではないが、調査回答全体が正式に完了したとは主張しない。

HTMLに採用した休憩の検査結果と不採用候補の未確認件数を別表示した。未取得情報をsupportedへ書き換えたり、タスクのpartialをsucceededへ変更したりしていない。

## 次回の生成へ反映する観点

修正観点を問題・問い・行動として保存し、新規タスクにも自己改善による再生成にも適用する。今回は休憩場所の営業範囲、追加調査と代替、行程の距離とペース、視覚的な魅力、採用先と任意候補の区別、通貨表記の6観点を登録した。本人の指摘と、ホスト検証で発見した問題の由来を分けている。

終了時にホストが検査結果を保存する。実際の次回context読込みでは、休憩の検査通過件数が1→2へ増え、以前の確認不足1件も消さずに残った。これは次回へ渡すデータの読み直しで、さらにもう一回モデルを実行した測定ではない。魅力など自動判定していない観点はnot-evaluatedとして保持する。過去の営業時間を今回の証拠に流用せず、モデルの重みも更新していない。

## 検証と再現

- 型検査、ビルド、303テストが成功。24時間開放の対象・否定文・駐車場の誤用、通貨表記、保存と再読込み、履歴の最近順、既定IDの上書き防止を含む。
- 実生成の回答ハッシュと全引用を照合。主案の休憩5手順と全行程を独立に再検査。
- 320/390/768/1280px × 明暗の8条件で写真、休憩表、行程展開、横はみ出しとページエラーを検査。
- 新旧HTMLのコントラスト68条件、以前の行程state成果物、配布プレビューを検証。

二回の実モデル生成を行った。二回目は任意候補の扱いを問い合わせでも明確にしているため、同一入力による成功率の比較ではない。生成後には回答を変えず、休憩表・観点のHTML表示と履歴管理の補強を加えて再描画・再検証した。生成時のruntimeRevisionと公開時のrenderRevisionは別に記録している。

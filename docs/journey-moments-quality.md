# 移動・休憩まで楽しめる行程の品質

「移動・休憩も含めた11手順を見る」を、開く前に一日のペースが分かる行程パネルへ変更した。移動・食事・体験・休憩・帰り支度をアイコンと配色で区別し、体験には実画像確認済みの掲載写真を添える。移動は破線のカード、休憩は温かい色のカードで示す。

## 自律生成の契約

`journey-map.moments` は元の `actionPlan.steps` と一対一に対応する。`stepId`、`kind`、`title`、`invitation` をモデルが生成し、ホストが順序と対応を検証する。重複・手順の抜け・不明なIDを拒否する。移動や休憩を落とした成果物は自己改善ループで合格にしない。

- 誘いかけは具体的な過ごし方の提案。上野では「午後の元気をためる」「発見を持って駅へ」などを実生成した。
- 時刻、場所、所要時間、進め方、完了条件、料金、未確認事項は元の構造化回答から表示する。モデルが見栄えのために書き換えない。
- 未確認の景観・席・店・設備を追加しない。休憩場所が不明なら現地確認と切替行動を示す。
- 写真は主活動に対応する既存の保存画像を使用。移動や休憩の風景として別施設の写真を流用しない。
- 元の主案を全手順表示する。地図で任意の立寄りを省略しても、主案の保存記録は変更しないと明示する。

## 別ケースで見つけた問題と改善

浅草・押上の実行では、古いHTMLの写真が`main`等の要素の外にあり、料理写真を拾えなかった。ロゴだけを料理写真として採用せず、品質検査が改善案を不採用にした。そこで本文内の画像を追加候補にし、ヘッダー・フッターと見出し画像・装飾・電話番号画像を除外する抽出へ改善した。候補の見た目は引き続きモデルが実画像を確認する。

型付き出力の形式エラーでは、選択された地図/ロードマップの枝に絞ったフィールド単位の診断を返す。別種の成果物の必須項目を混ぜて修正を促さない。

人生計画の過去回答は、同一住居の徒歩条件に矛盾があり、視覚改善だけでは採用されなかった。事実検査を緩めず、新しいサンプル相談で公開情報を取得し直してからロードマップを生成した。個人の年収・貯蓄・採用見通しを推測していない。

# 3案比較・内容の差・10秒レビューの改善ループ

[旅行の3案](comparison-travel.html#proposal-comparison)と[人生計画の3案](comparison-life.html#proposal-comparison)は、保存された実調査回答からモデルが生成し、共通の改善ループで採用した出力。元の行程・予算・根拠・未確認事項を保持する。

## 何を比較するか

`visualArtifact.proposalSet.options`に3案を保存する。発見・ゆったり・記録の3テーマを、比較する・一つへ集中する・記録を残す、という異なる仕組みに分ける。各案には具体的な行動、残る成果、希望に合う理由、定番との違い、不向きな条件を記載する。旅程では元の地点・手順に結び付け、活動時間をその枠内に収める。人生計画では元の節目の中で試す小さな行動にする。

初期表示は、入力で明示された優先条件と希望語との対応から決める。人間の魅力度スコアや効果の実測値ではない。利用者は自由に案を切り替えられ、ブラウザ内に同じ版の選択を保持する。元の保存行程の書き換えや、追加費用・移動の実行はしない。

## 独自性と実行条件の検査

- 異なる3テーマ・3つの仕組み・一意なIDを必要にする。
- 見出しを除いた「行動＋残る成果」の文字2-gram類似度を検査し、0.72を超える案の組を差し戻す。元の活動のほぼそのままの再掲も検査する。
- 元の地点・手順・引用への対応を確認し、活動枠を超える時間や不明な地点を拒否する。
- 類似度は重複を見つける補助で、意味の独自性や魅力を保証するものではない。人による「違いが分かりにくい」という評価を次の生成に渡す。

旅行の最初の実行では、比較案を追加する際に写真の必須項目まで落として不採用になった。既存の視覚成果物に問題がなく比較案だけ不足する場合は、`finish_proposals`で3案のみを提出する。ホストが地図・写真・全行程を保持するので、関連しない部分をモデルが再生成する失敗を避けられる。

## 10秒レビュー

画面で「表示中の案で10秒レビューを始める」を押すと、その案へ移動する。タブが見えている時間だけを計測し、10秒後に次の質問を出す。途中で案が変わったら再開始する。理解・未確認事項・次の行動・魅力1〜5を本人が明示的に選ぶまで保存できない。

ファイルとして開いたHTMLは、レビューJSONを書き出す。送信したとは表示しない。ローカルruntimeの回答エンドポイントから開く場合は、同一オリジンの保存APIを使う。

```sh
# 実際に自分でレビューしたJSONだけを取り込む。
# 旅行の今回の実生成Taskを保存したローカルStoreの例:
RUNTIME_DIR=.runtime/proposal-comparison/review-store node dist/cli.js ux-reviews import /path/to/ux-review.json
```

保存したTaskを直接レビューする場合は、同じStoreでWebを起動し、`/api/tasks/<task-id>/answer.html`を開ける。画像も同じTaskの保存アセットから配信し、評価を自動的に保存する。

```sh
RUNTIME_DIR=.runtime/proposal-comparison/review-store node dist/cli.js web --port 4317
# http://127.0.0.1:4317/api/tasks/bfe00831-5b99-4b78-afd5-3c1b12ed996e/answer.html
```

レビューはTask ID、回答内容・案・表示コードを含む版ハッシュ、対象の案、ブラウザの匿名識別子に結び付ける。同じ版・ブラウザ・案の回答は最新だけを改善に使う。別の版の評価は流用しない。匿名識別子は独立した人間の証明ではなく、その人数を人間の参加者数とは呼ばない。

## 次の改善への反映

`UxFeedbackStore.learningContext`は版ごとの自己申告レビューを集約し、「情報を減らす」「行動と成果の違いを明確にする」「希望との対応や実行条件を見直す」などの改善指針へ変換する。

offline視覚改善では保存Taskの集計をモデルへ渡す。通常の自己改善では、同じ指針をサイズ制限付きの`ImprovementContext.uxGuidance`へ入れ、sandbox側にも渡す。過去のレビューは新しい成果物の魅力度の点数や、事実確認の根拠へ転用しない。モデル重みの学習ではない。

## 実生成と検証

[実生成記録](evidence/proposal-comparison-generation.json)と[ブラウザ検証](evidence/proposal-comparison-qa.json)を参照。旅行は3案の追加以外の地図・写真・行程を保持し、人生計画は節目ID・時間軸・依存関係と元の回答本文を保持し、節目の説明文は再構成した。自動検査は案の切替・再読込・モバイル表示・10秒未満の禁止・非表示時間の除外・JSON書き出し・保存APIのオリジン保護・評価から次のモデル入力への伝達を確認する。

人間の評価はまだ収集していない。自動テストの回答は一時領域の識別子・凍結評価用のコピーだけを使い、本番の評価へ取り込まない。実際の人間による魅力度は未評価であり、5人の独立した評価を得たとは扱わない。

新しい版の魅力度は再評価が必要。過去の低評価を受けて生成した案でも、自動的に高評価とみなしてbestを差し替えない。共通の採否基準を保ち、不採用の試行も保存Taskから開いて比較・再評価できる。

# 写真と地図から旅を理解する生成ループ

実際の生成回答: [写真付きの上野旅行](generated-answer.html)。HTMLと隣の `answer-assets/` を一緒に保存して開く。画像は保存済みなので、旅行の写真を見るための外部リクエストは不要。Google Mapsと背景地図はオンライン表示。

## 地図の表示方針

1. 取得した施設ページに公式のGoogle Maps共有iframeがあれば、それをプレビューする。モデルにURLを作らせず、ホストが保存ページから抽出・検証する。同じ施設の根拠が必要。
2. 共有iframeがない地点、オフライン、iframeエラー、8秒間ロードしない場合は行程マップを表示する。国土地理院の現行ベクトルタイルを使い、道路・水域・建物・鉄道を静かな配色で描く。ピンと選択情報、訪問順を重ねる。
3. iframe内部は別オリジンなので、ホストから描画の成否を完全には判断できない。アクセス拒否ページでもloadが発火し得るため、「表示されない場合は行程マップへ」を常に置く。ロード完了だけを実地図表示の検証に数えない。
4. 訪問順の破線は道路に沿った経路ではない。実経路はGoogle Mapsへのリンクで確認する。Googleのデータやブランドを模倣した独自地図とは称さない。

参考: [Googleの共有・埋め込み](https://support.google.com/maps/answer/7101463?hl=ja)、[Embed API（APIキーが必要）](https://developers.google.com/maps/documentation/embed/embedding-map)、[国土地理院ベクトルタイル](https://maps.gsi.go.jp/development/vt.html)。通常のAPIにキーなしの非公開URLを捏造する方法は採用していない。

## 体験を生成する手順

`inspect_photo` → 実画像の確認 → 型付きexperience生成 → 写真保存 → 品質検査 → 共通自己改善ループで採否判定、の順に実行する。Codexへ画像データ自体を渡す。URLやaltだけで画像を選ばない。

- 主となる全活動に、写真、内容を表す見出し、時刻・場所・所要時間、楽しみ方、具体的な行動を付ける。任意の博物館も省略して合格にはしない。
- 施設・料理・展示の写真を使い、ロゴ、広告、案内バナーを除く。写真に写っているものを説明し、当日の展示・献立・利用可否を保証しない。
- 写真は保存済みページの参照に限定。モデルが実際に確認した画像であること、出典の対応、保存成功、SHA-256の一致を検査する。欠損した写真付き回答を視覚品質の成功に数えない。
- 元の本文、料金、候補判定、未確認事項は保持する。見栄えを理由に事実の確度を上げない。
- `--offline-visual` は追加の事実調査を行わない。保存ページに記録された写真の取得はあり得る。重みの追加学習ではない。

## 実生成と検証

実モデルの採用回答は `63666bf7-64ca-465a-9264-f75b0ca1d61e`。4候補の実画像を確認し、博物館の案内バナーを除外してクマの展示写真を採用した。写真3枚と3つの体験を生成した。記録は [travel-story-generation.json](evidence/travel-story-generation.json)。

[ライブ検証](evidence/map-background-live.json)はfile/HTTPの両方で、Google iframe内の画像描画、3枚の写真のデコード、行程マップの実タイル描画、OSMタイル通信ゼロを確認する。単なるiframe loadの検査とは別にしている。

[ブラウザ検証](evidence/visual-artifact-qa.json)は外部通信を模擬して、4画面幅、エラー時の切替、選択連動、予算切替、オフライン、ロードマップ依存関係を検査する。10秒以内の操作可能性は検査するが、人間の「魅力的」という評価は未採点。

再現用の `examples/visual-travel-answer.json` は実出力の凍結スナップショットで、本文資料は引用箇所のみ残す。`node scripts/generate-visual-examples.mjs` は推論も通信もしない表示再生。人生ロードマップは架空条件の操作例。これらを新しいモデルの能力評価や学習済みの成果とは扱わない。

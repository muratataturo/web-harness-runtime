# 無人で正式な旅行回答まで仕上げる

`npm run test:itinerary:live` はログイン済みCodexと公式の公開資料を使い、自然言語の依頼から旅程・候補比較・地図・写真を生成して実ブラウザで検査する。完成回答のJSONや人が編集した前回回答はモデルへ渡さない。モデル出力を合格させるために編集もしない。アカウントとネットワークを使うため通常のCIでは自動実行しない。

毎回 `.runtime/autonomous-itinerary/<日時>/` に独立したStoreを作り、`latest.json` を最初に不合格の状態で更新する。終了時に成功・失敗とTask IDを保存する。過去の成功で直近の失敗を隠さない。成功したときだけ `docs/autonomous-cafe-day.html` と写真、引用だけを残した再生用スナップショット、公開検証記録を出力する。

## runtimeの進め方

- 各主要ページの取得直後に引用を保存する。資料を全部集めてから引用を記録する進め方を避ける。
- 複数施設の旅程は `plan_task` の全条件に `appliesTo` を要求する。動物園の休憩所とカフェの商品価格を別施設へ課さない。時間枠・合計予算・写真は行程の共通検査で扱う。引用収集後に条件を緩めない。
- `read_task_state` が取得済みページ、施設の同一性、引用ID、草案、直近エラー、不足工程を返す。本文は `read_page` で再読する。返すページ・引用の数を制限し、省略数を明示する。
- `stage_plan` と `stage_visual` が最終提出の前にも品質の不足を返す。候補比較を直すときに保存済みの行程と写真を失わない。
- モデルが保存前に返答を終えたら、実際のチェックポイントを渡して最大3ターン再開する。2回連続で引用・行程・視覚草案に進展がなければ停止する。元の時間・ステップ・取得ページ数の上限は維持する。失敗を成功へ変更する処理はない。
- 行程などの構造化が必要なCodexタスクは推論努力をmediumにする。単純な事実確認はlow。エンジンやモデルの自動切替は行わない。

## PDFの色・配置を確認する

テキスト化だけでは開園カレンダーの色やメニューの価格配置を失う。`inspect_pdf_page` は取得時に保存した同じPDFのページを画像にしてモデルへ渡す。再取得した別文書や人が解釈した文章で代用しない。SHA-256、ページ番号、画像を渡した日時をTaskに記録する。画像の解釈を `record_evidence` の引用文に書き足すことは認めない。

PDFは従来の公開GET・接続先・DNS・転送・HTTP拒否の規則で取得し、16MiB・20ページまで。解析と描画は時間8秒・JSヒープ上限付きのworker内で行い、外部リソース取得とevalを無効にする。描画は最大辺2000px・400万画素、出力4MiB、1タスク8回まで。中間canvasも1600万画素を上限に検査し、大きな埋め込み画像が白紙になる回帰をテストする。ネイティブ描画メモリをJSヒープ上限だけで完全に隔離できるわけではない。保存PDFは非公開Storeの `pdf-assets/` に置き、公開成果物には含めない。

unpdf 1.6.2、PDF.js 6.5.438、@napi-rs/canvas 0.1.100を固定。描画時のCanvasFactoryは文書作成前に渡す。実装参照: [unpdf](https://github.com/unjs/unpdf)、[CanvasFactoryに関する公式リポジトリの報告](https://github.com/unjs/unpdf/issues/53)。Node 22.13以降の実行を対象にする。

写真確認の取得失敗もツールの修正可能なエラーとして返す。別の取得済み写真を試せるが、確認していない写真を採用したことにはしない。sandboxの回収時もPDFの文書ハッシュ・有効なページ・記録の対応を検査する。

## 合格条件と限界

ライブ生成はTask成功、候補の適用条件充足、引用の完全性、具体性・カフェ・視覚の共通品質ゲート、改善診断completeを要求する。主案の費用は掲載価格のみで予算内、席はarrival-check、対象日と5確認項目も必要。実HTTPで正式表示、比較表、写真2枚以上のデコード、行程リンク、全手順、320/390/768/1280pxで横はみ出しがないことを検査する。

モデルの意味解釈・徒歩時間・将来の営業を完全に証明する検査ではない。写真や空席、予約、在庫、将来価格の保証を追加しない。単一ケースの成功は一般の成功率や人間の魅力度の向上を示さない。人による魅力度評価と、モデルの重みの学習は実施していない。

`node scripts/eval-autonomous-itinerary.mjs` は保存した無編集出力の表示回帰のみを検査する。通常CIに組み込み、ライブ成功の代用にはしない。ライブ検証は毎回のネットワーク取得と推論を伴う別の検証として記録する。

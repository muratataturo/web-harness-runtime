# 時間帯と気分に合わせる旅程runtime

[実生成の比較HTML](experience-cases.html) — [結果と検証範囲](experience-depth-results.md)。

「一日」を短い観光リストへ縮めないため、依頼から時間の範囲とペースを保存する。時刻指定がない「一日・日帰り」は09:00〜20:00、「午後だけ」は13:00〜17:00、「寄り道・短時間」は14:00〜16:00を**提案**する。明示された時間範囲を優先し、仮定を回答に表示する。現地出発・帰着までの枠で、自宅からの交通時間は含まない。

一日には午前の具体的体験、昼食、午後の体験やカフェ、休憩、夕食、夜の帰路を必要とする。ゆっくり過ごす半日・短時間では主な観光体験を2枠以内に絞る。行程・写真に対応する手順の上限を16から32へ増やし、食事・徒歩・待ち・休憩を省略せず表現できるようにした。時間帯を埋めるだけで魅力を保証するものではなく、写真・見どころ・実際にすることはモデルが公開資料から生成する。

## 検査 → 追加調査 → 再検査

1. `stage_plan`で手順の`kind`、実施設の`venueUrl`、引用付き`stepChecks`を保存する。
2. ホストが同一施設、引用の完全性、手順と引用IDの対応、営業時間と滞在時間、最終入場、商品価格の根拠を検査する。
3. `verify_steps`は不足手順に対応する取得済み本文の短い連続部分を返す。`deepResearch:true`なら同じ施設の既存リンクを営業時間・カレンダー・メニュー・FAQの関連度で選び、共通の回数・ページ・時間予算内で追加取得する。
4. モデルが新しい本文から引用を保存し、行程・検査宣言を修正して再提出する。取得しただけではunknownを解消しない。
5. `finish_task`でも再検査する。調査不足なら予算内で追加調査へ戻す。修正回数が尽きても未確認を成功へ変えない。行程変更後はハッシュも再計算する。

追加調査と検査を`step_deepresearch`、`step_verification`イベントへ記録する。既存の具体性評価に未確認・衝突を組み込むため、自己改善の`diagnose`も同じ検査で未完了を検出する。継続プロンプトへも不足状態を渡す。サンドボックスからの成果物はホストで意図と検査結果を再計算し、ゲストの成功フラグを信用しない。

モデルに検査用の任意JavaScriptや正規表現を実行させる実装ではない。型と上限を持つ宣言を、固定されたホスト処理で検査する。未知URLを推測せず、別施設・アクセス拒否への迂回も行わない。

## 判定の範囲

営業時間検査は引用に記載された数値枠と行程の対応を確認する。曜日、対象日、休館告知、ランチ／ディナーの意味解釈を完全に証明しない。`fact`は指定語句の存在確認であり、自然言語全体の含意を証明しない。掲載価格は共通の引用・合算検査と組み合わせる。移動は見積、空席・当日の受付や提供は当日判断のまま表示する。

明示時刻の既存依頼は時間範囲を維持し、`stepChecks`を提出すれば同じ検査を適用する。新しい時間帯推定モードでは手順検査を必須とする。古い保存回答を再生成したり、過去の失敗判定を成功へ上書きする移行はしない。

候補条件の不足を集める際は`appliesTo`を考慮し、別施設に適用されない条件を追加調査へ送らない。複数業態を持つホテルでは展望施設とカフェの対象・取得契約を区別する。

## 検証用の実生成ケース

`hamamatsu-full`は朝から夜まで、`nagoya-afternoon`は午後だけ。時刻範囲を入力に書かず、runtimeの推定を検査する。完成行程・写真選択・価格JSONをモデルへ渡さない。候補の公式URLを入力しており、全国の店舗をゼロから発見する探索性能の評価ではない。

```sh
npm run build
node scripts/itinerary-live-e2e.mjs --live --case hamamatsu-full
node scripts/itinerary-live-e2e.mjs --live --case nagoya-afternoon
```

実生成の結果と表示検証は別々に記録する。未確認を残した成果物も、回答を手修正せず元の判定と合わせて公開する。

## 実生成から戻した修正

最初の浜松生成では「朝から夜まで丸一日、午後の体験…」の「午後の」を優先し、午後だけへ誤分類した。生成後の具体性検査が契約との衝突を検出し、正式な成功にはしなかった。「午後だけ・半日」の限定表現と、一日の途中の「午後の体験」を区別して修正し、同じ入力で再生成する。初回の失敗は`docs/evidence/experience-depth-iterations.json`へ残す。

夜の追加調査では、[公式ラウンジ案内](https://www.act-okura.co.jp/restaurant/lounge/)と[同名カフェ＆ラウンジのカクテルタイム資料](https://www.act-okura.co.jp/restaurant-plan/cafe_cocktailtime/)が未登録で、同じブランドの昼夜資料を結び付けられなかった。確認した個別パスを同一施設として登録した。展望回廊・他のレストランは別対象のままとし、昼の営業時間を夜の営業時間の代わりに使えるようにはしていない。料理ごとの提供枠も本文を読む必要がある。

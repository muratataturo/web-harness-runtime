# 浜松・名古屋での地域別実生成

[2地域の回答を並べて見る](regional-cases.html)。[浜松](hamamatsu-day.html#itinerary)と[名古屋](nagoya-day.html#itinerary)を、公式資料の新規取得から実モデルで生成した。本文・行程・写真選択・価格は手修正していない。

## 結果

2026年11月17日に資料取得・生成。依頼の対象日は11月21日（土）、大人2人、10:00〜15:00、現地の入館・飲食で合計1万円以内、交通費を除く徒歩中心の計画とした。地域の施設・カフェ・代替店の公式URLを調査して入力しており、候補URLゼロからの地域全店探索を実証したものではない。

両方で具体性・視覚・カフェの共通品質ゲートを通過し、表示可能な回答を保存した。一方、必須条件のunknownが残り、厳密なライブE2Eは両方とも不合格。`passed:false`と`Task.status:partial`を変更していない。表示回帰のpassは事実確認の完了を意味しない。

浜松では、入館800円×2、サラダ・コーヒー付きの食事2,000円×2、プリン600円×2を掲載額から計算。税・サービス料の扱いも引用されている。ただし主カフェの予約可否・注文方法の公開明記が取得できず、該当条件がunknownになった。休憩先の正確な階・入口・ベンチの当日利用、屋内の雨天代替も未確認として残る。

名古屋では、展示室500円×2、食事990円×2、単品コーヒー420円×2、ドーナツ400円×2を掲載税込額から計算。セット条件が未確認のため単品で計上した。休憩室固有の利用時間、カフェの注文・配膳・席予約の方式、サービス料などが未確認。4,620円を将来の最終支払額と保証せず、追加料金ゼロとも断定していない。

## 地域対応

従来の施設識別は東京中心だった。`src/regional-venues.ts`で、以下を版管理された対象として追加した。金額・営業時間・座標・完成行程はハードコードしていない。

- 浜松市楽器博物館の公式ドメインと名古屋市科学館の公式ドメインを、それぞれ単独施設として識別。
- ホテル運営会社のサイトはザ・シーズンカフェの個別店舗ページと対象メニューだけを同一対象とし、他レストランや総合一覧は個別候補として認めない。
- ノムラメディアスの科学館カフェ店舗、該当紹介記事、該当メニューPDFだけを同一対象とし、科学館本体とは別の比較対象にする。
- アクトシティの屋外広場を登録し、有料ホール・展望施設と無料休憩の条件を混同しない。所在地・利用時間・設備の意味を正しく理解したことを文字列検査だけで完全に証明するものではない。

公開GET・許可ホスト・DNS・転送・操作禁止パスの規則を維持した。任意の企業サイトや新しい外部ドメインを自動許可する変更ではない。観覧料の表組みにも対応し、別施設の根拠や別店舗を流用できないことを回帰テストで確認した。

入力は `scripts/itinerary-cases.mjs`。モデルは入力URLと依頼から引用、行程、予算、写真、座標を作成する。完成回答のJSONや東京の完成例はモデルへ渡していない。両地域は同じruntimeビルド・gpt-6.1-solで実行した。先行の東京の結果とはビルドや食事条件が異なるため、3地域を同条件の成功率として集計しない。

## 再現と検証

```sh
npm run build
node scripts/itinerary-live-e2e.mjs --live --case hamamatsu
node scripts/itinerary-live-e2e.mjs --live --case nagoya
```

認証・公開サイト取得・実推論を伴う。直近試行は `.runtime/regional-itinerary/<case>/latest.json`、各Storeと完全な取得本文は非公開領域に保存。正式判定が未達ならコマンドは非ゼロ終了し、成功へ置き換えない。保存回答が具体性・視覚ゲートを通っている場合には、次のコマンドで元の判定のまま配布用HTMLへ書き出せる。

```sh
node scripts/export-regional-run.mjs hamamatsu
node scripts/export-regional-run.mjs nagoya
node scripts/eval-autonomous-itinerary.mjs --case hamamatsu
node scripts/eval-autonomous-itinerary.mjs --case nagoya
node scripts/generate-regional-cases.mjs
```

書き出しは資料の本文を引用だけへ縮約し、固定CSSを共有資源に分ける。元の回答とスナップショットの回答ハッシュが一致することを検査。補完・行程変更・成功への再分類は行わない。公開記録の`publication`に、この再生用書き出しと元の判定保持を明記した。

全269テスト、両回答の320/390/768/1280pxの表示、全掲載写真のデコード、候補比較、5確認項目、行程リンク、全手順、横はみ出しを検査した。暫定回答には正式版の緑バッジが出ず、未確認が表示されることも確認。既存例と地域比較ページを含む48通り・21,846箇所の文字コントラストが通過した。人による魅力度や実地の徒歩・混雑・席は評価していない。

ライブの厳密判定と保存回答の表示回帰を分けてCIへ組み込んだ。通常CIでアカウント推論は実行しない。

今回確認できたのは、登録した地域公式ソースから写真・地図・行程・費用を生成し、情報不足を残した回答を表示できること。東京外のどの地域でも無設定で正式版が完成するとは主張しない。店舗の運用・追加料金・個別休憩所の利用時間など、公開されていない情報を確定に変える仕組みは入れていない。今後は条件を小さく分けて、確認済みの価格・営業と未確認の運用が一つのunknownへ埋もれないようにすることも改善対象になる。

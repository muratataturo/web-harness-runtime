# 読める回答と、理由のあるユニークな提案

[実生成した回答](asakusa-social-day.html#discoveries)には、既存の浅草・押上の行程内で選べる2案を追加した。通常の展示を別の見方で楽しむ独自案と、公式が告知した期間内だけ利用する案を区別している。

## 白文字の修正

Astryxのリセットは`color-scheme: light dark`を指定する。保存回答は明るい背景を使っていたが、テーマ指定がなく、OSのダークモードでシステムの文字色だけが白になっていた。再現時には上野60箇所、浅草58箇所、実生成の人生計画22箇所で、コントラスト比3未満の文字が見つかった。

保存回答の`html`へ`data-theme="light"`を設定し、本文の文字色と背景色も明示した。部品と本文の明色テーマを揃え、薄い注釈・時刻・依存関係の文字も濃くした。回答をダークモードのブラウザで開いても読める。明暗2設定×390/1280px×5回答の検査をCIに追加した。大きい文字は3以上、通常文字は4.5以上を基準に、透明な祖先背景を合成して検査する。外部地図iframe内部、写真、無効化した操作要素はこのDOM検査の対象外。

## SNSとトレンドの取得

`read_social`は公開情報の読み取り専用ツール。SNS・トレンドを依頼したクエリには、固定された公開SNSアダプターを調査元として追加する。通常調査では追加しない。ローカル、sandbox計画、回収時の検証で同じ許可ドメインとポリシーを使用する。ページ本文から接続先を無制限に追加しない。`RUNTIME_PROFILE=recruit/rakuten`で接続先を限定している場合は、その境界を保持する。SNSを併用する実行には`auto`または`public`プロファイルを使う。

- Blueskyの個別公開投稿URLを、公開のhandle解決APIとgetPosts APIで確認する。投稿日時、取得時点、いいね・再投稿・返信の数を保存する。欠損はnull、確認できた0件は0として区別する。
- X・Instagram・YouTubeの公開HTMLで投稿と反応数を検証できなければ未確認とする。現在、これらの反応数を正規化して取得するAPI連携は実装していない。
- Blueskyの検索APIは実確認で403だったため採用していない。別のホストやURL表記へ切り替えて拒否を回避しない。個別投稿URLは入力URLや公開ページのリンクから選ぶ。横断SNS検索や全投稿の人気ランキングを提供するものではない。
- 認証・投稿・予約・購入を行わない。1タスク6件、JSON応答256KB、各取得12秒を上限とし、保存ページ数の上限も守る。

参考: [Bluesky公式API案内](https://github.com/bluesky-social/bsky-docs/blob/main/docs/advanced-guides/api-directory.mdx)、[公式getPosts定義](https://github.com/bluesky-social/atproto/blob/main/lexicons/app/bsky/feed/getPosts.json)。

## 生成・自己改善の品質契約

`visualArtifact.discoveries`は地図と人生ロードマップの両方で利用できる。`anchorId`を既存の地点・節目へ結び付け、`headline / idea / whyNow / fit / fallback / evidenceIds`を生成する。

| basis | 根拠と表示 |
| --- | --- |
| social-snapshot | ホストが取得したsignalIdと引用が必須。30日を超えた投稿・取得記録を現在の話題として採用しない。数値はモデルに作文させず取得記録から表示する。 |
| official-event | 許可済みの公式施設ページ、開催期間の両日付の引用が必須。対象日と期間が合わなければ不採用。日付未指定の場合も開催期間中だけと表示する。 |
| original-idea | 独自の楽しみ方という提案。SNSの人気や確認済み事実と混同しない。 |

単一投稿の反応は、増加率、世間全体の流行、施設の品質ではない。根拠のない急上昇・バズ・SNS全体の人気の断定を拒否する。追加の場所・時間・費用を勝手に行程へ足さず、既存条件内での楽しみ方と、使えない時の代替を示す。

SNSを求めたのに取得可否の記録やユニークな提案がなければ、共通の視覚品質ゲートで差し戻す。凍結評価ではツール側でもSNSの新規取得を禁止する。offline視覚改善はSNSへの新規通信をしない。先に保存されたSNS取得結果と公式情報を使い、事実と元の行動計画を保持する。

## 実生成と検証

[生成記録](evidence/social-discovery-generation.json): 2案を実モデルで生成し、共通改善ループで採用した。元の10手順、13,900円の予算、2回の休憩を保持。SNSの反応は未確認であることを画面に残した。期間限定案は[すみだ水族館の公式告知](https://www.sumida-aquarium.com/news/4q4iptlvr3/)を参照し、期間外の通常鑑賞も併記する。

[公開SNSの実取得検証](evidence/social-public-live.json): 公開APIから実在投稿の数値を取得できたが、投稿自体が古いため、現在の旅行のトレンドには使わない検査が働いた。反応数を創作したり、古い話題を現在の流行へ変換したりしていない。

[明暗・コントラスト検証](evidence/answer-contrast-qa.json)とユニットテストでは、取得拒否、数値改変、古い投稿、期間不一致、非公式の期間情報、保存上限、未確認時の表示を検査する。人間の魅力度は未採点。

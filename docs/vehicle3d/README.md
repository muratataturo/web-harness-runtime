# 写真からの3D精度改善を実行した結果

[実際の比較・回せる3D・採否ログを開く](index.html)。ローカルのブラウザで開ける自己完結HTMLです。表示用メッシュは粗い格子で軽量化し、実際の高解像度モデルは実行先の `.runtime/vehicle3d/<run>/` に保存します。

2026-11-18には、ユーザー指定の240×180画像を `gpt-6.2-astra` に渡し、生成コードをBlender 4.5.3で実行しました。93部品の外観モデル・概略三面図PDF/DXF・運動学的走行GIF・操舵と車輪回転を含むBlenderアニメーションを作成しました。寸法と背面・内部形状は仮定を含みます。その再現コードを `scripts/vehicle3d/` に整理しています。[前回の概略三面図PDF](prior-drawing.pdf)と[走行軌跡の縮小画像](prior-motion.jpg)も掲載します。[当初の生成入力](../../examples/vehicle3d/astra-generation-prompt.txt)も残しています。rawのモデル会話ログや大きなモデルは公開対象にしません。

今回の自律runtimeは、日産公式の諸元と360°ビューを追加取得し、手描き形状の微修正から、複数写真の輪郭による形状復元へ進めました。現行runtimeは数値処理とレビュー済みBlenderスクリプトを実行し、LLMは呼びません。`gpt-6.2-astra` の使用は前回の初期コード生成です。LLMが新しい測定値や見えない機構を確定したとは記録しません。

## 実行で確認した改善と未達

| 検査                                      | 結果                                | 意味                                                        |
| ----------------------------------------- | ----------------------------------- | ----------------------------------------------------------- |
| 格子選択に使わなかった最終12方向の輪郭IoU | 0.8324 → 0.9055（+7.31ポイント）    | 画像上の輪郭が改善                                          |
| 選択用12方向のIoU                         | 0.8342 → 0.9031                     | 160格子の案を採用                                           |
| 224格子の案                               | 0.9035、棄却                        | 現採用案との差が採用条件0.001に届かず、三角形数を増やさない |
| 最終12方向への写真色の再投影              | 平均約14.1 dB                       | この試作の設定閾値20 dBに未達                               |
| 寸法拘束の残差                            | `result.json` に保存                | 座標正規化の成立を確認。実車への誤差保証ではない            |
| 実車精度の認証                            | 未達、常にfalse                     | 独立した実測・カメラ較正・公差の証拠が不足                  |
| runtimeの最終状態                         | `improved-incomplete` / 終了コード2 | 輪郭だけで完成扱いしない                                    |

[計測値](result.json)、[イベント履歴](events.jsonl)、[取得した根拠とSHA-256](evidence.json)、[ソースと成果物のハッシュ](receipt.json)を保存しています。候補選択用の視点を最終テストと混同しないよう、復元用12・選択用12・最終テスト12の3集合を分離しました。最終テストも同じ公式360°画像系列内であり、独立した実物撮影による物理検証ではありません。

表面の凹凸、写真の投影ずれ、影の混入、下面・凹面の未復元が残ります。見た目の粗さは[改善後の実レンダリング](after.jpg)にそのまま残し、輪郭スコアの向上を高品質な面復元の証明に置き換えていません。PSNRはsRGBの前景共通領域で、深度順に描いた三角形の平均頂点色を比較した値です。人間の知覚品質や機械設計精度の規格値ではありません。

## 何を根拠にしたか

- [元のユーザー指定画像](https://img1.kakaku.k-img.com/images/smartphone/icv/240x180_K0001791382.jpg)。この小画像の正確なグレードは未確認。
- [日産公式・外観と360°ビュー](https://www3.nissan.co.jp/vehicles/new/kicks/exterior.html)。YBUのG e-4ORCE表示を復元用のプロファイルに採用。
- [日産公式・主要諸元PDF](https://www-asia.nissan-cdn.net/content/dam/Nissan/jp/vehicles/kicks/2606/pdf/kicks_2606_specsheet_01_v1.pdf)、2ページ。日本仕様G e-4ORCEは全長4365・全幅1800・全高1610 mm、ホイールベース2655 mm。人が読んだ値を設定し、runtimeは取得物のハッシュを記録。諸元の意味を自動抽出・検証するエージェントではありません。

写真の枠合わせは推定アフィンカメラです。実カメラの透視投影やレンズ・歪みを較正していません。寸法の正規化と逆カメラ変換を同時に適用し、画像への投影を保っています。改善前モデルにも同じ座標変換を適用して、比較スコアが変わらないことを確認します。したがって、数値上の寸法一致は、実車と独立に一致を証明した測定ではありません。

## PRに含めたもの

再現用Python、`npm run vehicle3d`、設定、ユニットテスト、CI、比較HTML、計測JSON、縮小画像です。`.blend`、`.glb`、`.stl`、`.npz`、原寸写真、ダウンロードしたPDF、ZIP、大きな実行ログは含めません。前回の `artifacts/` もGit対象外にしています。

実行・再現方法は[スクリプトのREADME](../../scripts/vehicle3d/README.md)を参照してください。現時点は専用CLIとしての自律実行です。既存のChatやMCPへの経路追加、学習型の単眼3D再構成、SfMによるカメラ較正、OEM CADへの照合、RCバギーやエンジンの組立機構認識は未実装です。

より高精度な機械設計モデルに進むには、較正済みの追加撮影や実測点、OEM CADの入手と照合、公差・材質・可動軸の定義が必要です。これらがない状態で「近似ではなく正確」とは認定しません。

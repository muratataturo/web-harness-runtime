# 行程stateの実生成と検証結果

「9:00〜20:00なのに行程が短い」「移動・滞在の過去stateを参照したい」に対応し、場所・移動区間・訪問・待ち・休憩を結び付ける検証をruntimeと自己改善に追加した。[実際の生成回答をHTMLで開く](hamamatsu-experience-state.html#journey-state)。回答内容は人手で編集していない。

## 実生成

浜松の実モデル実行後、既存の`improveTask`で同じ問い合わせ・条件から一回の無人改善を実施した。モデルは`gpt-6.1-sol`。資料本文は再取得し、以前の回答を新しい証拠にしていない。

| 指標 | 再生成結果 |
| --- | --- |
| 時間帯 | 09:00出発〜20:00帰着 |
| 手順 | 移動・休憩を含め25手順 |
| 体験 | 浜松城、楽器博物館、展望回廊 |
| 食事 | 昼食、カフェ、夕食 |
| 写真 | 5枚 |
| 予算 | 大人2人で16,400円の計画値 |
| 徒歩 | 算出できた区間の推定3,886m、徒歩本体の計画105分 |
| 過去state | 過去の生成案2件、本人の移動・滞在実績0件 |
| 行程state | passed：区間の接続・時間内訳・最低滞在等の指摘0件 |
| 全体判定 | partial：施設情報の未確認事項が残る |

距離は引用した座標の直線距離に仮の迂回係数1.3を掛けた見積で、実道路経路の距離ではない。歩速・滞在時間は初期の計画仮定を使っており、利用者の実績を学習した結果ではない。移動枠全体には徒歩以外の館内移動・待ち・余裕も含む。

## 自己改善の採否

実行された一回の改善では、元案の19:10終了から20:00帰着へ延びた。一方、城周辺の二つの休憩手順（a2/a8）は休憩場所そのものの営業時間の引用が不足し、城・周辺施設等の個別詳細、対象日の確認にも未解消項目がある。営業時間・空席などが全て確定した正式行程とはしていない。

元の改善ループは`completed_partial`で、候補を採用しなかった。その後、行程stateの整合性と一日の時間枠を独立した達成項目に加えた判定器で同じ回答を読み直したが、既存の城の営業時間確認が退行しているため、引き続き`wouldAdvance: false`となった。時間枠の改善と引き換えに事実確認を失った案を自動採用しない。

初期生成から途中の生成へは候補資料も追加しているため、三回の生成を同一入力による性能比較や成功率改善とは扱わない。公開HTMLは実際の改善候補を確認するための成果物であり、自動採用済みという意味ではない。

## 検証

- 単体・統合テスト299件成功。状態遷移、施設の階移動、訪問の再入場、移動の方向、座標の引用、履歴の期限と識別、履歴なし、改善判定の非退行を検査した。
- 実生成回答のハッシュと全証拠の引用整合性を照合。回答JSONを編集せず、公開用の描画だけを再生成した。
- 実生成HTMLを320/390/768/1280pxと明暗の8条件で検査。写真5枚の読込、25手順の展開、距離・滞在表、横はみ出し・ページエラーなしを確認した。320pxで長い出典URLがはみ出す不具合も折返しを修正した。
- 既存回答と合わせたコントラスト検査64条件も成功。既存の旅行・人生計画・カフェの表示検査も実行した。

これらの表示検査は外部通信を遮断した状態で実施する。Google Mapsの外部プレビューや道路の通行可否、当日の空席の実地確認を意味しない。
